# MAIDOL 설치 앱 바로 업데이트(OTA) 안내 — v3.391 (2026-10-21)

웹은 배포하면 바로 바뀌지만, 설치 앱은 지금까지 스토어에 새 빌드를 올려야만 바뀌었습니다.
v3.391부터 앱에 **EAS Update(OTA)** 가 들어가, 화면·글자·로직(JS) 수정은 스토어 심사 없이 바로 내려보낼 수 있습니다.

> 이 기능은 **v3.391이 들어간 새 빌드(1.3.3)부터** 작동합니다. 지금 설치된 1.3.2 이하 앱은 OTA를 받지 못하니,
> 1.3.3을 스토어에 한 번 올린 뒤부터 쓸 수 있어요.

## 1. 무엇을 OTA로 보낼 수 있나

| 바꾼 것 | 방법 |
|---|---|
| 화면, 문구, 버튼, 계산·흐름(.ts/.tsx 파일) | **OTA 가능** |
| 이미지·아이콘 같은 앱 안 그림 파일 | OTA 가능 |
| 새 라이브러리 설치(`npx expo install …`), `app.json`(권한·플러그인·아이콘·스플래시·앱 링크), `modules/` 안 네이티브 코드(Kotlin) | **OTA 불가 → 새 스토어 빌드** |

헷갈려도 괜찮습니다. 배포 스크립트가 자동으로 검사해서, 네이티브가 바뀌었으면 OTA를 막고 "새 빌드가 필요해요"라고 알려 줍니다.
(원리: 빌드마다 네이티브 부분의 지문(fingerprint)이 runtime 번호가 되고, OTA는 같은 번호의 앱에만 내려갑니다.)

## 2. 사용자 쪽에서는 이렇게 보입니다

1. 앱을 켜면 뒤에서 조용히 새 업데이트를 받습니다(기다리게 하지 않음).
2. 받아 두면, 작업 중 화면(작사·작곡·커버·영상·채팅 등)이나 **음악 재생 중이 아닐 때만**
   「새 기능이 준비됐어요 — [나중에] / [지금 적용]」 창이 뜹니다.
3. [나중에]를 누르거나 창을 못 봐도, **다음에 앱을 새로 켤 때 자동으로 적용**됩니다.
   사용하는 도중에 앱이 갑자기 다시 켜지는 일은 없습니다.
4. 설정 > 버전에 `v1.3.3 (16·10211530)`처럼 보입니다 — `16` = 빌드 번호, `10211530` = 받은 업데이트 시각(10월 21일 15:30).
   문의가 오면 이 글자로 어떤 버전인지 정확히 알 수 있어요.

## 3. 채널(받는 대상) 두 가지

| 채널 | 받는 앱 |
|---|---|
| `preview` | 대표님 시험용 APK(eas build --profile preview) |
| `production` | 스토어(Play·App Store)에서 받은 앱 |

**항상 preview 먼저 → 대표님 폰에서 확인 → production** 순서로 보냅니다.

## 4. 'JS 수정 → OTA 배포' 순서 (Claude 세션이 대신 실행, 운영 반영이라 대표님 승인 후)

```bash
cd /Users/pearl/TripleJ/2_housing
git fetch origin && git rebase --autostash origin/frontend      # 다른 세션 작업과 합치기(덮어쓰기 사고 방지)
./scripts/ota_update.sh preview "v3.392 버튼 글자 수정"            # 1) 시험 앱에 먼저
```
대표님 폰에서 MAIDOL을 껐다 켜서 확인(또는 앱으로 돌아와 [지금 적용]) → 이상 없으면:
```bash
./scripts/ota_update.sh production "v3.392 버튼 글자 수정"         # 2) 스토어 앱 전체에
```

스크립트가 하는 일: ① 타입 검사(tsc) ② eas.json 같은 프로필의 광고 단위 등 값 적용 ③ 네이티브 호환 검사(맞는 빌드가 없으면 그 플랫폼은 건너뛰고 "새 빌드 필요" 안내) ④ `eas update` 업로드.
미리 확인만 하려면 `DRY_RUN=1 ./scripts/ota_update.sh production "…"`.

## 5. 잘못 보냈을 때 되돌리기

```bash
npx eas-cli@latest update:rollback      # 묻는 대로 채널(production) 선택 → 바로 전 업데이트 또는 처음 설치본으로
```
되돌린 것도 사용자 앱이 다음에 켜질 때 적용됩니다. expo.dev > 프로젝트 triplej-studio > Updates 에서 기록을 볼 수 있어요.

## 6. 스토어 업데이트 안내(필수·선택)와의 관계

- OTA로 안 되는 수정(네이티브)은 예전처럼 스토어 빌드 → 서버 `/api/app/version` 설정으로 안내합니다.
- v3.391부터 앱이 **빌드 번호**도 비교합니다. 서버 설정에 `android.min_build`·`latest_build`(iOS도 같은 이름)를 넣으면
  버전 글자(1.3.3)가 같아도 "빌드 17보다 낮으면 업데이트 안내"처럼 정확히 고를 수 있어요.
  (서버가 이 두 값을 내려주도록 바꾸는 것은 별도 승인 항목 — 바꾸기 전에는 지금처럼 버전 글자만 비교)
- 빌드 번호는 EAS가 빌드마다 자동으로 1씩 올립니다(시험 APK·스토어 빌드 모두).

## 7. 알아 둘 점

- OTA 배포 = 운영 반영입니다. 웹 배포와 같이 **대표님 승인 후** 실행합니다.
- 광고 단위: 앱 코드에 정식 광고 단위가 기본값으로 들어 있어, OTA로 보내도 테스트 광고로 바뀌지 않습니다.
- 스토어 정책: 앱 성격을 바꾸는 큰 변경은 OTA가 아니라 스토어 심사로 보내는 게 원칙입니다(버그 수정·문구·화면 개선은 OTA OK).
