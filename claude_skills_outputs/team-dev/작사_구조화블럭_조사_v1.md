# 작사 프롬프트 "구조화 블럭" 자료 조사 (v1, 2026-08-31)

## 결론 한 줄
구조화 블럭의 재료(태그 체계·LLM 프롬프트)는 **MAIDOL 백엔드에 이미 완성**돼 있고, MAIDOL 프론트엔 태그 삽입 버튼까지 있음. **AIDOL만 통짜 텍스트** — 격차는 프론트 UI 하나이며, 태그 파싱 기반 "블럭 보드"로 백엔드 무수정 도입 가능.

## ① 우리 자산 현황
- **MAIDOL 프론트** (StudioTab2.jsx:193, 2611~2631): `[Verse] [Chorus] [Bridge] [Outro] [Intro] [Pre-Chorus] [Instrumental]` 태그 버튼 바 — 누르면 커서 위치에 삽입. 단 본문은 통짜 textarea(3,000자) — 완전한 블럭 에디터는 아님.
- **MAIDOL 백엔드** (lyrics_generator.py:55~330): LLM 시스템 프롬프트가 섹션 태그 필수·태그+창법 조합(`[Verse: soft, whispered]`)·장르별 구조 가이드·최소 구조 규칙(`[Intro]+2x[Verse]+[Pre-Chorus]+[Chorus]+[Bridge]+[Outro]`)·듀엣 파트 태그(`[Female]/[Male]/[Both]`)까지 규정. **생성 가사엔 이미 태그가 들어옴.**
- **AIDOL 현재**: 구조는 선택지 문자열('절—후렴' 등)로 자연어 프롬프트에 녹이고, 결과는 통짜 TextInput 편집·통짜 저장(lyricsBookStore `lyrics: string`). 태그 파싱/편집 코드 전무 — 서버가 태그 포함 가사를 줘도 그냥 텍스트로 표시 중.

## ② Suno가 인식하는 구조 태그
- 신뢰도 높은 태그: `[Intro] [Verse]/[Verse 1,2] [Pre-Chorus] [Chorus] [Hook] [Bridge] [Breakdown] [Instrumental] [Outro] [End]` + 형용사 결합(`[Soft Verse]`, `[Powerful Chorus]`).
- 규칙: 섹션 가사 바로 윗줄 단독 라인, 후렴 반복 시 태그 반복, **태그는 영어·가사는 한국어**(Suno가 대괄호를 지시로 읽음), Style이 아닌 **가사 필드**에.
- 한계: 태그는 확률적 힌트(대부분 따르지만 무시 가능) → 무시되면 재생성이 정석 = "블럭별 재생성" UI가 실용적인 이유.
- 표준 구조: Intro → Verse → Chorus → Verse → Chorus → Bridge → Chorus → Outro.

## ③ 타 서비스 사례
- **LyricStudio(WaveAI)**: 송 섹션 빌더 + 라인 단위 AI 제안(운율·음절).
- **Lyric Blocks(iOS)**: 벌스/코러스/브릿지 블럭 추가·복제·드래그 재배열.

## ④ AIDOL 도입 제안 — "가사 블럭 보드" (1안)
작사 결과 화면을 통짜 입력 대신 섹션 블럭 리스트로:
- 블럭 카드 = {종류(벌스/코러스/브릿지/…), 라벨, 가사 텍스트} / ▲▼ 순서 변경 / ⋯ 메뉴(이 블럭만 다시 쓰기·복제·삭제) / [+ 블럭 추가] / [전체 미리보기].
- **파싱**: 서버 가사를 정규식 `\[([^\]]+)\]`로 split — 신규 백엔드 작업 불필요.
- **저장/작곡 호환**: 블럭을 `라벨\n가사`로 join하면 기존 `lyrics: string`과 100% 호환(보관함·musicService 무수정).
- **단계적 도입**: 1단계 = 프론트 전용(블럭 편집·순서·수동 수정)만으로 출시 가능. 2단계 = "이 코러스만 다시"(백엔드 엔드포인트 1개 — MAIDOL 프롬프트 재활용). 최소 대안 = MAIDOL식 태그 삽입 버튼 바만 이식.
