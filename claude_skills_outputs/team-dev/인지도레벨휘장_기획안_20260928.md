# MAIDOL 아티스트 인지도·레벨·휘장 시스템 — 기획안 v1 (2026-09-28)

> 대표 요청: "가상팬덤 재생 팝업을 아티스트 인지도로 반영, Lv1 연습생부터 인지도에 따라 레벨 상승, 레벨에 따라 휘장 변경 — 구체화"
> 조사 방식: 앱·서버 실코드 분석 + 운영 데이터 읽기 전용 실측 (유저 55·아티스트 25·트랙 75)

## 1. 현재 상태 (설계의 갈림길)
- **"가상 팬덤이 N회 재생" 팝업은 100% 클라이언트 연출** — 서버는 모름. 앱 진입 시 24h마다 `아티스트Lv×5+기획사Lv×3+발매곡×2` 공식으로 가짜 재생수 생성(일 10~150회), 기기 저장소에만 기록 → 기기 바꾸면 리셋.
- 기존 "레벨"은 아티스트별이 아니라 유저당 1개인 레거시(멀티 아티스트 이전 유물, 이모지 등급표 🌱⭐ — 현행 규칙 위반). 레벨업 토스트 인프라(levelUpQueue+LevelUpModal)는 재사용 가능.
- 실지표 인프라 완비: 재생 기록에 본인 재생 여부(is_owner)가 이미 기록되고(v3.230), 차트는 본인 재생 제외 — 인지도도 같은 기준이면 공정성 논리 일관.
- ⚠️ 과거 재생 로그의 97%는 3~4월 시드 데이터(가짜 유저 1만) — 소급 계산 시 제외 필수.

## 2. 인지도(RP) 공식 — 실지표가 앵커, 가상 팬덤은 연출(캡)
| 신호 | RP | 가드 |
|---|---|---|
| 곡 발매 | +100 | 첫 발매 = 즉시 Lv2 "데뷔" |
| 실재생 1회(타인) | +2 | 본인 재생 제외(차트 기준 재사용) |
| 하트 | +20 | 취소 시 -20 |
| 다운로드 | +30 | 최고 단가(실화폐 연동 신호) |
| 공유 | +10 | 유저·곡당 일 1회 |
| 가상 팬덤 재생 | +0.2 | **일 상한 +30 RP** — 방치만으론 Lv4까지만 |
- 아티스트별 누적, 감쇠는 MVP 미도입(소규모에선 박탈감만 큼).

## 3. 레벨 테이블 (8레벨, 지수 곡선)
| Lv | A안(추천) | B안 | 필요 RP | 현재 데이터 기준 |
|---|---|---|---|---|
| 1 | 연습생 | 연습생 | 0 | 곡 없는 아티스트 |
| 2 | 데뷔조 | 데뷔 | 100 | 첫 발매 즉시 |
| 3 | 신인 | 첫 무대 | 250 | 2곡+소량 반응 |
| 4 | 라이징 | 음방 데뷔 | 600 | 현 중상위권 |
| 5 | 아이돌 | 1위 후보 | 1,500 | 현 1위(≈900~1,000 RP) 근접 |
| 6 | 스타 | 음방 1위 | 4,000 | 베타 이후 목표 |
| 7 | 슈퍼스타 | 대상 후보 | 10,000 | — |
| 8 | 레전드 | 명예의 전당 | 25,000 | — |
- 현 1위 아티스트 소급 ≈ Lv4 후반 — "다 만렙"도 "영원히 Lv1"도 아닌 분포. 신규는 첫 발매로 즉시 승급 팝업 → 첫날 체감 보장.

## 4. 휘장 디자인
- 컨셉: **"마이크 스탠드의 성장"** 단일 모티프 + 금속 티어 — Lv1 무광 이름표 → 브론즈/실버/골드 마이크(별 추가) → 플래티넘 → 홀로그램+월계수 → 다이아 프레임 → Lv8 블랙&골드 왕관. 이모지 금지, 벡터(SVG) 8종.
- 노출: ① 내 아티스트 카드(좌하단 오버레이) ② 아티스트 상세 헤더("Lv.5 아이돌") ③ 채널 ④ 플레이어 인라인 ⑤ 차트·클럽(Phase 3).
- 제작: **정적 SVG 8종 추천**(비용 0·일관성·다크테마 대응). 생성형 커스텀 휘장은 Lv7+ 특전으로 예약.

## 5. 보상 연계 (추천: A)
- **A. 레벨업 ⭐ 지급** — Lv2:10 / 3:20 / 4:30 / 5:50 / 6:80 / 7:120 / 8:200 (아티스트당 1회, 총 510⭐). 기존 포인트 시스템으로 즉시 구현, 생성 루프 재투자 유도.
- B. 기능 해금(슬롯 등)은 Phase 3, C. 순수 명예는 비추천.

## 6. 아키텍처
- 저장: characters 문서에 `recognition:{rp, level, updated_at}`.
- 집계: 이벤트 증분($inc — 재생·하트·발매·다운로드 훅 한 줄씩) + 일 1회 배치(가상 팬덤 보너스·정합 보정) — 단일 워커 안전(기존 60초 동기화 선례와 동급).
- 가상 팬덤 **서버 이관 추천**(Phase 2): 팝업 숫자=인지도 1:1 일치 + 기기 리셋 문제 해결.
- 앱: /character/list의 level 변화 감지 → 기존 레벨업 큐 재사용 → 토스트 + "새 휘장 공개" 다이얼로그.

## 7. 구현 단계
- **Phase 1 (서버 1일+앱 1~2일)**: RP 훅 4종 + 레벨 테이블 + SVG 휘장 8종 + 카드/상세/채널 노출 + 기존 25명 소급.
- **Phase 2 (1~2일)**: 가상 팬덤 서버 이관 + 아티스트별 청취 리포트 개편 + 휘장 공개 연출 + ⭐ 보상 + 레거시 제거.
- **Phase 3**: 차트·클럽 연계, Lv7+ 커스텀 휘장, 감쇠 검토.

## 8. 대표 결정 5가지
1. 레벨 명칭 A안(연습생~레전드) vs B안(무대 서사)
2. 레벨업 ⭐ 보상 채택 여부 (총 510⭐/아티스트)
3. 가상 팬덤 서버 이관 (Phase 2 포함 여부)
4. 휘장 = 정적 SVG 8종(추천) vs 생성형
5. 기존 아티스트 25명 소급 승인 (시드 데이터 제외 기준)

## 9. 리스크
- 인플레이션: 가상 팬덤 캡 필수(적용됨). 단가는 상향만 가능(하향은 박탈) — 보수적 시작.
- 소급 오염: 시드 로그 제외, tracks 누적치 기준(±5~10% 오차 허용).
- 성능: 증분+배치 구조라 부담 없음. 앱 추가 요청 0건.
