관리자 주소 이전 + 광고주 사이트 만들기

2026-10-19 · 대표님 확인용 계획과 화면 시안입니다. 아직 서버와 DNS는 아무것도 바꾸지 않았습니다. 화면 시안의 숫자와 상품은 모두 예시입니다.

한눈에 보기① 관리자 주소 이전② 광고주 사이트 시안어디에 올릴지광고주 계정 발급서버 보강결정해 주실 것진행 순서·대표님 할 일

0한눈에 보기

① 관리자 웹 → admin.maidol.ai.kr
  • 화면과 기능은 지금과 같습니다. 주소만 바뀝니다.
  • 옛 주소(api.maidol.ai.kr/admin)로 들어오면 새 주소로 자동 이동합니다.
  • 새 주소에서는 관리자 기능만 열립니다. 앱이 쓰는 API(api.maidol.ai.kr)는 그대로라 앱에는 영향이 없습니다.
  • 관리자분들은 새 주소에서 한 번만 다시 로그인하시면 됩니다(로그인 정보는 주소별로 따로 저장됩니다).
② business.maidol.ai.kr — 브랜드·광고주용
  • 소개 페이지: MAIDOL 광고·입점 안내 + 문의하기.
  • 광고주 전용 화면: 로그인 → 대시보드(착장 선택·클릭·클릭률·담김) → 내 상품 등록·수정·노출 켜고 끄기 → 상품별 성과.
  • 서버에 광고주 기능이 이미 있어서, 화면을 새로 만들고 서버는 몇 군데만 보강합니다.
  • 금액·과금은 결정 전이라 화면 어디에도 넣지 않았습니다.
지금 광고주 계정 현황 (운영 DB에서 읽기만 해서 확인)
  • 광고주 계정 8개: 무신사·gucci·29cm·W컨셉·에이블리·지그재그·크림·브랜드샵. 모두 우리가 만든 운영용 계정이고, 실제 브랜드에 넘긴 계정은 아직 없습니다.
  • 상품 수: 브랜드샵 8,185개, 무신사 167개, 크림 120개 순. 최근 30일 기록은 착장 선택 885회, 클릭 14회, 담김 13회입니다.
  • 그래서 광고주 사이트는 새로 받을 실제 브랜드(상품 수십 개 규모)를 기준으로 만들고, 상품이 수천 개인 운영용 계정도 느려지지 않게 목록을 페이지로 나눕니다.

①관리자 주소 이전 (api.maidol.ai.kr/admin → admin.maidol.ai.kr)

바뀌는 흐름

admin.maidol.ai.kr→관리자 화면 /admin+관리자 API /api/admin/…, 로그인 /api/auth/login→기존 서버(같은 컨테이너)
api.maidol.ai.kr/admin (옛 주소)→301 영구 이동→admin.maidol.ai.kr/admin
api.maidol.ai.kr 나머지 전부(앱이 쓰는 API)→변경 없음

확인한 것

  • 관리자 웹은 API를 상대 주소(/api)로 부릅니다. 그래서 새 주소에서도 코드 수정 없이 같은 서버로 연결되고, 다른 주소 간 통신 허용(CORS) 설정도 필요 없습니다.
  • 관리자 웹이 부르는 API는 /api/admin/…과 /api/auth/login 두 종류뿐입니다. 새 주소에서는 이 두 가지만 열고 나머지는 막습니다.
  • 새 주소의 첫 화면(/)은 /admin으로 보냅니다. 화면 주소에 #가 붙는 방식이라 새로고침해도 깨지지 않습니다.
  • 서버 프로그램(컨테이너)은 다시 시작하지 않습니다. 서버 앞단(nginx) 설정만 추가하고, 추가 전에 설정 검사(nginx -t)와 백업을 합니다.

보안 강화(선택): Cloudflare Access

관리자 주소 앞에 회사 메일 인증을 한 겹 더 거는 방법입니다. 관리자 웹 로그인 전에 Cloudflare 화면에서 @lotusai.co.kr 메일로 받은 6자리 코드를 넣어야 들어갈 수 있습니다. 50명까지 무료입니다.
  • 장점: 관리자 주소를 아는 외부인은 로그인 화면조차 볼 수 없습니다.
  • 필요한 것: 이 기능은 DNS 레코드의 프록시를 켜야(주황 구름) 동작합니다. 인증서는 처음에 프록시를 끈 상태로 발급하고, Access를 켤 때 프록시를 켭니다. 그때 Cloudflare의 SSL 모드가 "전체(엄격)"인지 함께 확인해야 합니다.
  • 추천: 먼저 주소 이전만 끝내고, Access는 대표님이 원하시면 이어서 2단계로 겁니다. 설정할 화면 순서를 따로 안내해 드리겠습니다.

광고주 계정 발급·비밀번호 운영 제안

추천: 관리자 웹에서 발급 → 임시 비밀번호 → 첫 로그인 때 변경
  1. 관리자 웹 '브랜드/광고주' 화면에 [광고주 계정 만들기] 버튼을 추가합니다. 회사명·담당자 이메일만 넣으면 계정이 만들어지고, 임시 비밀번호가 그 화면에 한 번만 보입니다. 관리자가 이 비밀번호를 담당자에게 전달합니다.
  2. 광고주가 임시 비밀번호로 처음 로그인하면 새 비밀번호를 정해야 다음 화면으로 넘어갑니다.
  3. 비밀번호를 잊으면 로그인 화면의 '비밀번호를 잊으셨나요?'로 이메일 6자리 코드 재설정(앱에서 쓰는 기능 그대로)을 쓰거나, 관리자 웹의 [임시 비밀번호 다시 발급] 버튼을 씁니다.
  4. 광고주 계정은 앱 로그인용 계정과 같은 표에 있지만, 역할이 '광고주'라서 광고주 사이트에 들어갈 수 있습니다. 모든 발급·재발급은 관리자 웹 '관리 기록'에 남습니다.

다른 방법: 초대 메일(no-reply@maidol.ai.kr)로 "비밀번호 설정 링크"를 보내는 방식. 관리자가 비밀번호를 볼 일이 없어 더 깔끔하지만 만들 것이 늘어납니다. 우선 위 방식으로 시작하고 필요하면 바꾸는 것을 추천합니다.

광고주 기능은 대부분 이미 있습니다. 아래만 고치면 됩니다. 서버 재시작은 진행 중인 작업이 0건일 때 한 번(약 10초) 합니다.

  • 상품 목록 페이지 나누기·검색: 지금은 최대 200개까지만 돌려줍니다(브랜드샵은 8,185개). 기존 앱 동작은 그대로 두고 쪽 번호·검색 조건만 추가합니다.
  • 대시보드 합계: 지금은 상품 500개까지만 더해서, 상품이 많은 계정은 합계가 작게 나옵니다. 전체 상품을 더하도록 고칩니다.
  • 기간 기준을 한국 시간으로: 지금 '오늘'이 한국 시간 오전 9시부터 계산되고, '이번 주·이번 달'은 월요일·1일에 0으로 돌아갑니다. 차트(v3.378)와 똑같이 '오늘 / 최근 7일 / 최근 30일'(한국 시간)로 맞춥니다. 관리자 웹 브랜드 화면에도 같이 적용됩니다.
  • 회사 정보 저장 오류: 처음 저장할 때 특정 경우 실패하는 오류가 있어 함께 고칩니다.
  • 관리자용 광고주 계정 만들기·임시 비밀번호 다시 발급(새로 추가), 첫 로그인 비밀번호 변경 표시.
  • 입점·광고 문의 접수(Q3에서 양식을 고르시면): 문의를 저장하고 관리자 웹에 '광고 문의' 목록을 추가합니다. 같은 사람이 짧은 시간에 여러 번 보내지 못하게 막습니다.
