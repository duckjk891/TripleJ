## ① 프롬프트 작성 공식

```
┌──────────────────────────────────────────────────────────────┐
│ AS-IS (실제 코드)                                              │
│ 파일: mv_generator.py:1170-1244                                │
│                                                                │
│ SCENE_SPLIT 시스템 프롬프트엔 이미 강한 공식이 박혀있음:         │
│   • Shot type      (extreme wide → close-up)                  │
│   • Camera angle   (eye-level / low / high / bird's / dutch) │
│   • Lighting       (natural / golden / backlit / rim / neon) │
│   • DoF            (shallow bokeh / deep focus / rack)        │
│   • Color palette  (warm / cool)                              │
│   • Camera motion  (track / pan / tilt / dolly / handheld)    │
│                                                                │
│ → 거의 영화학교 교과서 수준의 공식이 이미 적용됨               │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│ TO-BE (Higgsfield/업계)                                       │
│ MCSLA 공식 (Motion + Camera + Subject + Lighting + Atmosphere)│
│ + K-pop 특화 패턴 + 50개 K-pop MV few-shot 예시                │
└──────────────────────────────────────────────────────────────┘

[차이점]
공식 자체는 이미 있음. 다만:
  - 우리는 일반 시네마 공식 → K-pop 특화 패턴 부재
  - few-shot 실제 K-pop MV 샘플 0개
  - 따라서 "K-pop 톤"이 살짝 약할 수 있음

[개선 효과] 중간 정도. 우선순위 낮음.
```

## ④ 주인공샷 우선 (첫 등장 클로즈업)  ★ 높음

```
┌──────────────────────────────────────────────────────────────┐
│ AS-IS (실제 코드)                                              │
│ 파일: mv_generator.py:1170-1244 SCENE_SPLIT                   │
│                                                                │
│ 도입 규칙은 단 한 줄, 모호함:                                    │
│   "Introduction (first 2-3 scenes):                            │
│    Set the scene, introduce the mood/character/setting"        │
│                                                                │
│ → "정적 클로즈업으로 인물부터 보여줘라" 같은 강제 규칙 없음    │
│                                                                │
│ Phase 1.5는 캐릭터 시트만 생성하고                              │
│ 등장 순서 / 주인공샷 강제엔 관여 안 함                          │
└──────────────────────────────────────────────────────────────┘

[현재 흐름 (문제)]
  씬1: 한지유가 거리를 달린다 (인물 + 액션 동시 등장)
  씬2: 한지유가 옥상에서 노래한다
  씬3: 한지유가 클럽에서 춤춘다
       └ 매 씬마다 모델이 "이 인물 누구지?" 다시 학습
       └ 외모가 씬마다 미세하게 변동 (drift)

┌──────────────────────────────────────────────────────────────┐
│ TO-BE (Zephyr K-pop 시리즈 패턴)                              │
│   • 새 인물의 첫 등장은 무조건 "정적 클로즈업"                  │
│   • 카메라 줌인만 허용, 인물 동작 거의 없음                      │
│   • 그 다음 씬에서야 "행동" 가능                                 │
└──────────────────────────────────────────────────────────────┘

[개선 후 흐름]
  씬1: 한지유 정면 클로즈업, 정적, 카메라 줌인만   ← "이 사람 누구"
  씬2: 한지유가 거리를 달린다                       ← "이 사람이 행동"
  씬3: 한지유가 옥상에서 노래한다
       └ 시청자도 모델도 인물을 확실히 기억
       └ 일관성 큰 폭 향상 + "영화 같다"는 느낌

[필요 작업]
  1. mv_generator.py:1170+ SCENE_SPLIT 시스템 프롬프트에
     "ABSOLUTE 주인공샷 RULE" 블록 추가:
       - 새 캐릭터 첫 등장은 STATIC CLOSE-UP만 허용
       - subject motion은 두 번째 등장부터 가능
  2. character_first_seen 추적 로직 추가 (이미 등장했는지)
  3. 검증 게이트: 주인공샷 룰 위반 시 해당 씬 재생성 (1회 한도)
```

## ⑤ Kling 다각도 캐릭터 참조

```
┌──────────────────────────────────────────────────────────────┐
│ AS-IS (실제 코드 — 의외로 이미 3장 보냄)                        │
│ 파일: kling_video_generator.py:63-134                          │
│                                                                │
│ 함수 시그니처:                                                  │
│   image_bytes              ← 현재 씬 first frame              │
│   prev_scene_image_bytes   ← 이전 씬 (연속성용)               │
│   character_image_bytes    ← 캐릭터 시트 (정면 1장)            │
│                                                                │
│ 매 호출 시 Kling에 3장 전송:                                    │
│   <<<image_1>>>: 현재 씬                                       │
│   <<<image_2>>>: 이전 씬                                       │
│   <<<image_3>>>: 캐릭터 시트                                    │
└──────────────────────────────────────────────────────────────┘

[차이점 — 핵심]
"몇 장이냐"가 아니라 "어떤 정보냐"가 다름.

  우리: 캐릭터 = 정면 시트 1장
  TO-BE: 같은 인물의 다각도 4장 (정면/측면/뒷면/클로즈업)

┌──────────────────────────────────────────────────────────────┐
│ TO-BE (Kling Element Library)                                 │
│   • 캐릭터당 다각도 ref 4장 미리 등록                           │
│   • element_id 1개로 호출, Kling이 다각도 조합해서 이해         │
│   • 등 돌아도, 측면 봐도 같은 사람                              │
└──────────────────────────────────────────────────────────────┘

[개선 후 차이]
  지금: 등 돌아 춤추는 씬에서 뒷모습 헛소리                       
  바꿈: Kling이 뒷모습 ref 학습해서 일관 유지                     

[필요 작업]
  1. Phase 1.5에서 캐릭터당 다각도 4장 시트 생성
     (Gemini/Nano Banana로 정면/측면/뒷면/얼굴 클로즈업)
  2. Kling Elements API 통합 (element 등록 + element_id 발급)
  3. kling_video_generator.py에서 element_id 우선 사용
  4. fallback: element 없으면 기존 3장 방식 유지
```
