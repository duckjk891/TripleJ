# MAIDOL 어린이 모드 기획서

2026-09-25

## 요약

이번 프로모션 버전에 **어린이 모드**를 넣어 초등학생(만 6~12세)도 MAIDOL을 쓸 수 있게 하고, Google Play 가족 정책 심사를 함께 받는다. 한 앱 안에서 생년월일로 계정을 나누는 "혼합 연령" 구조로 만든다. 어린이 계정도 작사·작곡·커버 생성과 듣기는 그대로 쓰고, 모르는 사람과의 DM, 실사 얼굴 사진, 보이스 클론, 맞춤 광고만 막는다.

**핵심 결정**

- **어린이 기준은 만 13세 미만**이다. Google이 아동으로 보는 기준이다.
- **만 14세 미만은 모두 보호자 동의 후 가입**한다. 한국 개인정보보호법 기준이며, 앱과 서버에 기능은 이미 있고 서버 설정만 꺼져 있다.
- **로그인하지 않은 사용자는 나이를 모르므로 어린이와 같은 광고 설정**을 쓴다.
- **제한은 서버에서 강제**한다. 앱 화면만 숨기면 API를 직접 호출해 우회할 수 있다.
- 등급 설문의 "채팅 조정", "초대된 친구로만 제한"은 이 기능들이 실제로 만들어진 뒤에만 "예"로 바꾼다.

## 배경: 지금은 초등학생이 가입할 수 없다

현재 앱은 만 14세 미만의 가입을 막고 있고, Play Console 등급은 12세 이상으로 나왔다. 초등학생을 받으려면 타겟층에 만 13세 미만을 넣어야 하고, 그 순간 앱 전체가 Google 가족 정책 심사 대상이 된다.

| 항목 | 현재 상태 (2026-09-25 확인) |
| --- | --- |
| 만 14세 미만 가입 | 차단. "보호자 동의 절차 준비 중" 안내 |
| 보호자 동의 가입 | 앱·서버 기능은 있음. 서버 설정 `guardian_consent_enabled`가 `false` |
| 콘텐츠 등급(IARC) | 12세 이상 |
| 광고(AdMob) | 아동용 설정 없음. 맞춤 광고·광고 ID 수집 그대로 |
| DM | 닉네임만 알면 누구에게나 보낼 수 있음. 팔로우하지 않은 사람은 "메시지 요청"으로 들어감 |
| 채팅 필터 | 없음. 신고 후 처리 |
| 얼굴·목소리 | 실사 사진으로 아티스트 생성, 얼굴 인증(생체정보), 보이스 클론 있음 |

**Google 가족 정책에서 우리에게 걸리는 조항** ([가족 정책 원문](https://support.google.com/googleplay/android-developer/answer/9893335))

1. **광고**: 아동과 나이를 모르는 사용자에게는 가족 정책 인증을 받은 광고 SDK만 쓰고, 관심사 기반 광고와 리마케팅을 하면 안 된다.
2. **기기 식별자**: 아동이나 나이를 모르는 사용자의 광고 ID(AAID) 등을 전송하면 안 된다.
3. **연령 확인**: 어른과 아이가 함께 쓰는 앱은 중립적인 연령 확인 화면이 있어야 한다. 가입 시 생년월일 입력이 이미 이 역할을 한다.
4. **소셜 기능**: 모르는 사람과 소통하는 앱은 아동을 대상으로 할 수 없다. 아동에게 온라인 안전 안내를 보여주고, 개인정보를 주고받기 전에 어른의 확인을 받고, **보호자가 아이의 소셜 기능을 관리할 방법**을 제공해야 한다.
5. **개인정보**: 아동에게서 수집하는 정보를 개인정보처리방침에 모두 적어야 한다. SDK가 수집하는 것도 포함한다.
6. **등급 설문**: 소셜 기능을 포함해 사실대로 답해야 한다.

가족 정책 본문에는 생성형 AI만을 다루는 별도 조항이 없다. 다만 아이에게 보여주는 콘텐츠는 아이에게 적합해야 한다는 일반 원칙이 AI 결과물에도 적용된다.

## 연령 구분 설계

계정은 가입할 때 받는 생년월일로 세 단계로 나뉘고, **서버가 나이를 계산해 내려준다.** 생일이 지나 만 13세가 되면 별도 작업 없이 일반 모드로 바뀐다.

| 구분 | 만 나이 | 가입 방법 | 앱 모드 | 광고 |
| --- | --- | --- | --- | --- |
| 어린이 | 13세 미만 | 보호자 동의 후 | 어린이 모드 | 아동용 |
| 청소년 | 13세 | 보호자 동의 후 | 일반 모드 | 일반 |
| 일반 | 14세 이상 | 바로 가입 | 일반 모드 | 일반 |
| 로그인 전 | 모름 | — | 둘러보기·듣기만 | 아동용 |

**서버가 내려줄 값**

- `/auth/me` 응답에 `age_group`(`child` / `teen` / `adult`)을 추가한다. 앱은 이 값만 보고 모드를 정하고, 생년월일을 직접 계산하지 않는다.
- 보호자 동의 상태와 보호자가 설정한 소셜 기능 허용 여부(아래 "보호자 관리")도 같이 내려준다.

**연령 확인 화면 (Google의 "중립적 연령 확인")**

- 생년월일을 묻기 전에 "13세 이상만" 같은 기준 나이를 보여주지 않는다. 아이가 나이를 속이도록 유도하지 않기 위해서다.
- 현재 만 14세 미만 차단 화면의 "이전으로" 버튼처럼 생년월일을 바로 다시 입력하게 하는 흐름은 없앤다. 어린이도 가입할 수 있게 되므로 차단 화면 자체가 사라진다.
- 가입 후 생년월일은 이용자가 직접 바꿀 수 없다. 잘못 입력했다면 고객센터에서 확인 후 고친다.

**보호자 동의와 보호자 관리**

- 만 14세 미만은 지금 만들어진 보호자 동의 흐름을 그대로 쓴다. 보호자 이름과 휴대폰 번호를 받고, 승인 전에는 로그인이 막힌다.
- 가족 정책이 요구하는 **보호자 관리 페이지**를 새로 만든다. 보호자가 동의 링크로 들어와 아래를 할 수 있어야 한다.
    - 피드 글쓰기·댓글 허용/금지
    - 친구(서로 팔로우)와의 DM 허용/금지
    - 동의 철회 및 계정 삭제 요청
- 위치는 `maidol.ai.kr/guardian` 같은 웹 페이지가 적당하다. 보호자는 앱을 설치하지 않았을 수 있다.

확인 필요: 지금 보호자 동의 링크가 문자로 가는지, 보호자 본인을 어떻게 확인하는지 백엔드에서 확인해야 한다. 가입 가능한 최소 나이(예: 만 7세)를 둘지도 정해야 한다.

## 기능별 어린이 계정 정책

음악을 만들고 듣는 핵심 기능은 모두 남기고, 아이의 얼굴·목소리·개인정보가 나가거나 모르는 사람과 연결되는 기능만 막는다. "보호자 허용"은 보호자 관리 페이지에서 켜야만 쓸 수 있다는 뜻이고, 기본값은 꺼짐이다.

| 기능 | 어린이 계정 | 이유 |
| --- | --- | --- |
| 차트·검색·듣기·플레이리스트 | 유지 | 개인정보·소통 없음 |
| 작사·작곡·커버 AI 생성 | 유지 + 입력·결과 필터 강화 | 핵심 기능. 아이에게 부적절한 가사·이미지를 막아야 함 |
| AI 아티스트 만들기 | 설명·그림체(가상) 방식만 | 이미 있는 "사진 없이 만들기" 경로를 사용 |
| 실제 얼굴 사진 올리기 | 끔 | 아이 얼굴로 AI 이미지를 만드는 위험 |
| 커버 배경 사진 올리기 | 끔 | 사진에 얼굴·위치가 들어갈 수 있음 |
| 얼굴 인증(생체정보) | 끔 | 아동 민감정보 수집 안 함 |
| 보이스 클론 | 끔 | 아이 목소리 데이터 수집 안 함 |
| 내 음원·참고 음원 올리기 | 끔 | 아이 목소리 녹음이 들어갈 수 있음 |
| 뮤직비디오 생성 | 유지 (가상 아티스트만) | 실사 얼굴이 없으니 위험이 낮음 |
| 곡 발행(차트 공개) | 유지 | 닉네임으로만 공개. 실명 쓰지 않도록 안내 |
| 피드 읽기 | 유지 | 신고된 콘텐츠는 처리 전이라도 어린이에게 숨김 |
| 피드 글쓰기·댓글·곡 댓글 | 보호자 허용 + 금칙어 필터 | 어른 확인 후 소통 |
| 피드·DM 사진 첨부 | 끔 | 얼굴·학교 등 개인정보 사진 노출 방지 |
| DM | 보호자 허용 시 서로 팔로우한 친구만 + 금칙어 필터 | 모르는 사람과 소통하면 아동 대상이 될 수 없음. 고객센터 공식 DM은 유지 |
| 다른 사람이 어린이에게 DM 보내기 | 친구가 아니면 불가 | 메시지 요청도 보낼 수 없음 |
| 프로필: 지역·SNS 주소·소개글 | 입력 안 함, 공개 안 함 | 개인정보 교환 방지 |
| 프로필 이미지 | 기본 아바타 또는 내 AI 아티스트 이미지만 | 실제 얼굴 사진 노출 방지 |
| 외부 공유(카톡 등 링크) | 유지 | 곡 링크만 나가고 개인정보는 없음 |
| 자체 광고·착장 쇼핑 링크 | 끔 | 어린이에게 구매를 유도하는 외부 링크 |
| 출석체크·스타·추천 코드 | 유지 | 결제·현금 보상 없음 |
| 보상형 광고 | 아동용 (비맞춤, 전체이용가 광고만) | 가족 정책 필수 |
| 신고·차단 | 유지 + 곡 댓글 신고 추가 | 곡 댓글만 지금 신고가 없음 |
| 온라인 안전 안내 | 새로 추가 | 가족 정책 필수. 첫 로그인과 피드·DM 처음 쓸 때 표시 |
| 회원탈퇴 | 유지 + 보호자도 요청 가능 | 보호자 관리 페이지에서 |

## 백엔드 작업 목록

## 광고(AdMob) 아동 설정

**쓰고 있는 AdMob은 아동용으로 쓸 수 있는 버전이고, 어린이에게 광고를 불러올 때 아동 설정만 켜면 된다.** 앱에 들어 있는 Android AdMob(`play-services-ads`)은 25.0.0이고, Google의 [가족 정책 인증 광고 SDK 목록](https://support.google.com/googleplay/android-developer/answer/9283445)은 19.0.0 이상을 인정한다.

**지금 상태**

- 광고는 보상형 하나뿐이다. "디렉터 휴식 중" 창에서 "광고 보고 30분 단축"을 누를 때만 나온다 (`utils/fatigueGate.ts:187-194`). 배너·전면 광고는 없다.
- 로그인한 사용자에게만 광고를 불러온다 (`hooks/useRewardedSkipAd.ts:80-83`). 나이를 모르는 로그인 전 사용자는 광고를 보지 않으므로 문제가 없다.
- 아동용 설정은 하나도 없다. 모든 사용자에게 같은 설정으로 초기화한다 (`useRewardedSkipAd.ts:196-216`).

**바꿀 것**

| 항목 | 어린이 계정 | 일반 계정 |
| --- | --- | --- |
| `tagForChildDirectedTreatment` (아동 대상 처리) | `true` | 설정 안 함 |
| `maxAdContentRating` (광고 콘텐츠 등급) | `G` (전체이용가) | 지금처럼 |
| `requestNonPersonalizedAdsOnly` (비맞춤 광고) | `true` | 지금처럼 |

- 설정은 앱이 켜질 때 한 번이 아니라, **로그인해서 `age_group`을 알게 된 뒤 광고를 불러오기 전에** 넣는다. 같은 기기에서 계정을 바꾸면 다시 설정한다.
- 아동 대상 처리를 켜면 Google이 맞춤 광고와 리마케팅을 끄게 된다. 어린이의 광고 ID가 전송되지 않는지는 AdMob 문서와 실제 요청으로 한 번 더 확인한다.
- 나중에 로그인 전 사용자에게도 광고를 보여주게 되면 어린이와 같은 설정을 써야 한다.
- 자체 광고(`/business/ads`)와 착장 쇼핑 링크도 광고로 보므로 어린이에게는 내보낸다 (앱 D2, 백엔드 F8).

## 개인정보처리방침·약관·동의 문구 수정

처리방침에는 만 14세 미만 조항(제10조)이 이미 있어서, **어린이 계정에서 달라지는 점만 더하면 된다.** 같은 내용이 세 곳에 있으니 함께 고쳐야 서로 어긋나지 않는다.

| 문서 | 위치 | 바꿀 내용 |
| --- | --- | --- |
| 개인정보처리방침 | `lotusai.co.kr/privacy` (홈페이지 저장소 `www/privacy/index.html`) | 제10조에 어린이 계정 항목 추가, 제2조 ⑨ 광고식별자에 예외 추가, 시행일 갱신 |
| 앱 안 동의 문구 | 앱 저장소 `constants/consentTexts.ts` | "[필수] 만 14세 이상 확인" 문구를 연령별로 나누고, 처리방침 개정 내용과 맞춤 |
| 계정 삭제 안내 | `maidol.ai.kr/delete-account` | 보호자가 자녀 계정 삭제를 요청하는 방법 추가 |
| 이용약관 | `lotusai.co.kr/terms` | 어린이 계정의 이용 범위와 보호자의 관리 권한 조항 추가 |

**제10조에 더할 내용 (초안)**

- ⑤ 만 13세 미만 회원(어린이 계정)에게서는 얼굴 사진, 얼굴 인증(생체정보), 음성 파일, 지역·SNS 주소·소개글을 수집하지 않습니다.
- ⑥ 어린이 계정과 로그인하지 않은 이용자에게는 맞춤형 광고를 보여주지 않으며, 광고식별자를 수집하거나 전송하지 않습니다.
- ⑦ 법정대리인은 보호자 관리 페이지에서 자녀 계정의 피드·댓글·메시지 기능 사용 여부를 정하고, 개인정보 열람·삭제와 동의 철회를 요청할 수 있습니다.

처리방침을 바꿀 때는 보통 시행 7일 전에 개정 내용을 공지한다. 법무 검토가 필요한 문구라, 회사 담당자 확인을 거친 뒤 게시한다.

## Play Console 제출 체크리스트

앱 작업이 끝난 뒤 아래 순서로 제출한다. 기능이 실제로 동작하기 전에 답을 바꾸면 안 된다. 아동이 포함된 앱은 심사가 더 오래 걸릴 수 있으니 여유를 둔다.

- [ ] **타겟층 및 콘텐츠**: 연령대에 6~8세, 9~12세를 추가한다 (13~15세, 16~17세, 18세 이상과 함께). 만 5세 이하는 넣지 않는다.
- [ ] **가족 정책 요건 확인**: 광고 SDK가 Google의 가족 정책 인증 목록에 있는 버전인지 확인한다.
- [ ] **콘텐츠 등급 설문 다시 제출**: 금칙어 필터가 모든 DM·댓글에 적용되면 "채팅 조정"을 예로, 보호자가 DM을 친구로만 제한할 수 있으면 "초대된 친구로만 제한"을 예로 바꾼다. 나머지 답은 지금과 같다.
- [ ] **데이터 보안 양식**: 어린이 계정에서 얼굴·음성·광고 ID를 수집하지 않는다는 점이 처리방침과 맞는지 확인한다.
- [ ] **로그인 세부정보(심사용 계정)**: 기존 성인 계정에 더해 **보호자 동의가 끝난 어린이 테스트 계정**을 만들어 등록한다. 심사자는 계정을 만들 수 없다. 보호자 관리 페이지에 들어가는 방법도 영어 안내문에 적는다.
- [ ] **광고 선언**: "예" 유지.
- [ ] **처리방침·계정 삭제 URL**: 개정본이 게시된 뒤에 제출한다.
- [ ] **스토어 등록정보**: 설명·스크린샷에 아이에게 부적절한 이미지가 없는지 확인한다.

## 일정·리스크·결정 필요 사항

**가장 오래 걸리는 건 보호자 동의를 실제로 보내고 확인하는 부분(E2)이다.** 문자·본인확인 업체 계약이 필요할 수 있어 가장 먼저 시작한다. 프로모션 날짜가 정해지면 아래 순서를 역산해 배분한다.

| 단계 | 내용 | 담당 |
| --- | --- | --- |
| 1 | 보호자 동의 발송·본인확인 수단 확정(E2), `age_group`(E1), 소셜 가입 연령 확인(E3), 생년월일 잠금(E4) | 백엔드 |
| 2 | 어린이 제한 API(F1~F8), 금칙어 필터(G1), 곡 댓글 신고(G2) | 백엔드 |
| 3 | 가입·연령(A1~A5), 소셜(B1~B8), 얼굴·목소리(C1~C7), 광고·링크(D1~D3) | 앱 |
| 4 | 보호자 관리 페이지(E5 + 웹 화면), 처리방침·약관 개정 게시 | 백엔드·웹·법무 |
| 5 | 어린이·성인 테스트 계정으로 전체 점검, Play Console 제출 | 전체 |

이후로 미뤄도 되는 것은 어린이 피드 필터(G3)와 프로필 완성 보상 조정(A5) 정도다. 나머지는 가족 정책 심사에 직접 걸린다.

**리스크**

- **심사 지연**: 아동이 포함된 앱은 심사가 길어질 수 있다. 프로모션 날짜보다 충분히 앞서 제출한다. 심사가 막히면 만 13세 이상 버전을 먼저 내고 어린이 모드를 업데이트로 붙이는 것이 대안이다.
- **보호자 확인 수단 없음**: 지금 동의 링크는 목 모드에서만 나온다. 실제 발송과 본인확인이 없으면 법적 동의로 인정받기 어렵다.
- **AI 결과물**: 생성형 AI는 가끔 예상 밖의 가사·이미지를 만든다. 어린이 계정 신고는 우선 처리한다.
- **App Store**: iOS도 출시한다면 Apple 연령 등급 설문을 같은 기준으로 다시 답해야 한다.

**결정 필요**

- [ ] 프로모션 날짜와 Play Console 제출 마감일
- [ ] 가입 가능한 최소 나이 (없음 / 만 7세 등)
- [ ] 보호자 동의 발송·본인확인 방식과 업체
- [ ] 금칙어 필터 방식 (자체 단어 목록 / 외부 API)
- [ ] 어린이 DM을 이번에 열지, 아니면 우선 완전히 끌지
