# 백엔드 요청 — 사용자 프로필 수정 엔드포인트

작성일: 2026-04-27
요청 출처: 모바일 앱 v41 (PLAN.md), 사전 누적: REPORT v15 / v22 (Settings 화면 placeholder 상태)

## 배경

현재 모바일 앱 Settings 화면에는 닉네임 변경 / 비밀번호 변경 입력 필드 자리만 있고 실제 PATCH 호출은 미구현 상태입니다. 백엔드 `auth.py`를 grep한 결과 **닉네임 / 비밀번호 / bio 등을 수정할 수 있는 엔드포인트가 부재**합니다 (`profile_image`만 `upload.py`의 `POST /api/upload` type=profile 경로로 업로드 가능).

## 요청 엔드포인트

### 1) `PATCH /api/auth/me/profile`

사용자 본인의 프로필 부분 업데이트.

**Request (모두 optional, 보낸 필드만 갱신)**
```json
{
  "nickname": "새 닉네임",
  "bio": "자기소개",
  "display_title": "대표",        // v30에서 추가된 호칭
  "company_name": "기획사 이름"   // v30에서 추가된 기획사명
}
```

**검증**
- `nickname`: 2~20자, 트림 후 공백 불가, 중복 시 `409 nickname_taken`
- `bio`: 최대 200자
- `display_title`, `company_name`: 각 30자 이내
- 빈 객체(`{}`) 요청은 `400 nothing_to_update`

**Response (200)**
```json
{
  "id": "uuid",
  "email": "...",
  "nickname": "...",
  "profile_image": "...",
  "bio": "...",
  "display_title": "...",
  "company_name": "...",
  "plan": "free",
  "role": "user"
}
```

**Error**
- `401 unauthorized`
- `409 nickname_taken`
- `400 invalid_field` (검증 실패 시 어떤 필드인지 detail에 포함)

### 2) `PATCH /api/auth/me/password`

비밀번호 변경. 현재 비밀번호 검증 후 갱신.

**Request**
```json
{
  "current_password": "현재 비밀번호",
  "new_password": "새 비밀번호"
}
```

**검증**
- `current_password` 일치 안 하면 `401 password_mismatch`
- `new_password`: 8자 이상, 영문+숫자 포함 (회원가입과 동일 규칙)
- 동일 비밀번호로 변경 시 `400 same_as_current`

**Response (200)**
```json
{ "ok": true }
```

세션 무효화 정책은 백엔드 판단에 맡깁니다. 무효화 시 `{ "ok": true, "logout_required": true }`로 알려주면 모바일에서 재로그인 유도.

**Error**
- `401 unauthorized` / `401 password_mismatch`
- `400 weak_password` / `400 same_as_current`

## 모바일 측 후속 작업

엔드포인트가 반영되면:
- `services/api.ts`에 `updateProfile(payload)` / `changePassword(payload)` 함수 추가
- `screens/SettingsScreen.tsx` placeholder 자리에 입력 필드 + 검증 + 호출 로직
- 응답 받은 사용자 객체로 `useAuthStore`의 user 갱신
- `logout_required: true` 응답 시 자동 로그아웃 + 로그인 화면
