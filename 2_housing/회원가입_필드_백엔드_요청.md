배경: 현재 프론트 Onboarding 화면에서 수집 중인 **기획사명/대표 호칭**이 로컬 zustand 메모리에만 있어 앱 재설치/다른 기기 시 사라짐. 회원가입 시점에 DB에 영속하도록 플로우를 앞당길 예정.

---

## 1. 왜 이 변경이 필요한가

- **문제**: 현재 흐름은 `회원가입(email/pw/nickname) → 앱 첫 실행 시 Onboarding(기획사명/호칭) → 로컬 zustand` 저장
- **결과**: 로그아웃/재설치/다른 기기 로그인 시 온보딩이 다시 뜸. DB엔 흔적 없음.
- **목표**: 회원가입 API가 기획사명/호칭을 함께 받아 DB에 저장 → `/auth/me`로 항상 조회 가능

---

## 2. 요청 변경 사항

### 2-1. DB 스키마 (`infra/init_postgres.sql` 또는 마이그레이션)

`users` 테이블에 **2개 컬럼 추가**:

```sql
ALTER TABLE users
  ADD COLUMN IF NOT EXISTS company_name VARCHAR(100),
  ADD COLUMN IF NOT EXISTS display_title VARCHAR(20);

-- 기존 사용자 대응 (NULL 허용, 앱이 fallback 처리)
-- 필요 시 default 값:
--   UPDATE users SET display_title = '대표' WHERE display_title IS NULL;
```

**네이밍 제안**
- `company_name`: 기획사명 (예: "이재규 엔터테인먼트"). 최대 100자.
- `display_title`: 호칭 (예: "대표님", "PD님"). 최대 20자. 기본값 "대표".

## 4. 호환성 / 마이그레이션

- **기존 가입자**: `company_name`, `display_title` NULL 상태. 프론트는 NULL일 경우 `nickname + " 엔터테인먼트"` / `"대표"`를 fallback으로 표시 (이미 구현됨).
- **미구현 클라이언트**: 구버전 앱은 회원가입 시 두 필드를 보내지 않음. 백엔드는 NULL/기본값 허용하므로 호환.
- **DB 롤백**: 컬럼 삭제보다 NULL 유지가 안전. 문제 생기면 코드에서만 사용 중단.

2. `Onboarding` 로직을 **SignupScreen**(신규)으로 옮기고 4단계 → 회원가입 단일 화면에 통합

4. 기존 `onboardingStore.ts`는 **제거**하거나 임시 → AsyncStorage 마이그레이션 헬퍼만 남김
5. `OnboardingScreen`은 삭제 (또는 "프로필 편집"으로 용도 변경)
