# 백엔드 터널링 (외부 접속) 설정 요청

## 요청일: 2026-04-18

## 목적

휴대폰의 **LTE/5G 데이터 환경**에서 Expo Go 앱을 테스트해야 합니다.
현재 백엔드가 사설 IP(`192.168.219.106:9003`)에 묶여 있어 LTE에서는 접속 불가.
**백엔드 PC를 인터넷에 노출**하여 휴대폰이 데이터 환경에서도 API를 호출할 수 있게 해주세요.

---

## 환경

| 항목 | 값 |
|------|---|
| 백엔드 PC | **Windows** |
| 프론트엔드 PC | Mac (Expo Dev Server) |
| 백엔드 포트 | 9003 (FastAPI) |
| 백엔드 IP | 192.168.219.106 (사설) |
| 테스트 디바이스 | iPhone/Android (LTE/5G) |

---

## 핵심 결론

**백엔드 코드 수정은 (거의) 필요 없습니다.**
- 이미 `CORSMiddleware allow_origins=["*"]` 적용 → 외부 도메인 허용 OK
- `TrustedHostMiddleware` 미적용 → Host 헤더 검증 안 함 → cloudflared 도메인 접속 OK

**운영(인프라) 작업만 필요**: 윈도우 PC에서 터널링 도구 실행.

---

## 윈도우 PC에서 해야 할 작업

### 1. cloudflared 설치 (둘 중 하나)

**옵션 A) winget**
```cmd
winget install --id Cloudflare.cloudflared
```

**옵션 B) MSI 직접 설치**
- https://github.com/cloudflare/cloudflared/releases
- `cloudflared-windows-amd64.msi` 다운로드 → 실행

### 2. 백엔드 서버 실행 확인

먼저 백엔드가 9003 포트에서 정상 작동 중인지 확인:
```cmd
curl http://localhost:9003/api/charts/top100
```
정상 응답 받아야 다음 단계 가능.

### 3. cloudflared 터널 실행

```cmd
cloudflared tunnel --url http://localhost:9003
```

출력 예시:
```
Your quick Tunnel has been created! Visit it at:
https://abc-def-ghi-jkl.trycloudflare.com
```

→ **이 URL을 Mac 측 프론트엔드 담당자에게 전달**해주세요.

### 4. URL 변경 시 처리

cloudflared quick tunnel은 **재실행 시마다 URL이 바뀝니다**.
- 한 번 띄우고 그대로 두면 같은 URL 유지 (24시간+ 가능)
- 윈도우 슬립/재부팅/Ctrl+C 시 URL 폐기됨
- URL이 바뀔 때마다 Mac 프론트에 다시 전달 필요

### 5. 윈도우 슬립 방지

테스트 기간 동안 PC 슬립을 끔:
- 설정 → 시스템 → 전원 → "절전 모드" → **"사용 안 함"**
- 또는 PowerToys "Awake" 사용

### 6. 방화벽

cloudflared는 outbound only (백엔드 인입을 위해 포트 개방 불필요).
- Windows Defender가 처음 실행 시 묻는다면 "허용" 클릭
- 일반적으로 별도 설정 불필요

## 백엔드 코드 확인 사항 (수정은 X, 점검만)

### ✅ CORS 설정 (이미 OK)

`app/main.py:67-73`
```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],          # 모든 origin 허용 ✅
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

→ **수정 불필요**. (참고: 엄밀히는 `allow_origins=["*"]`와 `allow_credentials=True`는 CORS 스펙상 함께 쓰면 안 되지만, RN/모바일 앱은 CORS 영향 없으므로 무관)

### ✅ TrustedHostMiddleware (미적용 → OK)

`app/main.py`에 `TrustedHostMiddleware` 없음 → cloudflared 도메인(`*.trycloudflare.com`)으로 들어와도 Host 검증 통과.

→ **수정 불필요**.

### ⚠️ 확인 필요: MinIO presigned URL이 사설 IP를 반환하는지

`/api/tracks/stream/{id}` 등 presigned URL을 반환하는 엔드포인트가 있다면:
- presigned URL의 host가 `192.168.x.x:9000` (사설 IP) 형태일 가능성
- 휴대폰이 LTE에서 이 URL로 접속 시도 → **실패**

**대응**: 이미 `/api/tracks/stream-proxy/{id}` 엔드포인트가 구현되어 있어 백엔드를 통해 프록시 스트리밍됨. 프론트는 stream-proxy를 사용하므로 **별도 수정 불필요**.

다만, 새로 추가될 프리사인 URL 반환 엔드포인트가 있다면 같은 패턴(stream-proxy)으로 처리 권장.

## 작업 순서 요약

| 단계 | 담당 PC | 작업 |
|------|---------|------|
| 1 | 윈도우 | 백엔드 서버(9003) 실행 |
| 2 | 윈도우 | `cloudflared tunnel --url http://localhost:9003` |
| 3 | 윈도우 | 발급된 URL을 Mac 프론트에 전달 |
| 4 | Mac | `services/api.ts`의 `BACKEND_HOST/PORT`를 cloudflared URL로 교체 |
| 5 | Mac | `npx expo start --tunnel` |
| 6 | 휴대폰 | Expo Go에서 터널 URL/QR로 접속 |

---

## 트러블슈팅

| 증상 | 원인 | 해결 |
|------|------|------|
| `cloudflared: command not found` | 설치 안 됨 또는 PATH 미적용 | 새 cmd 창 열기 또는 재부팅 |
| 휴대폰에서 차트 안 뜸 | 백엔드 URL 미적용 | Mac의 `services/api.ts` 수정 확인 |
| 갑자기 API 401/Network Error | 윈도우 슬립으로 터널 끊김 | 슬립 해제, 터널 재실행 (URL 바뀜) |
| 음악 스트리밍만 안 됨 | presigned URL이 사설 IP | `/api/tracks/stream-proxy/{id}` 사용 확인 |
| Expo Go 접속 자체 안 됨 | Expo 측 터널 미실행 | Mac에서 `npx expo start --tunnel` |

## 장기 운영 시 권장 (선택)

매번 URL이 바뀌는 게 불편하면 **cloudflared named tunnel** (영구 도메인) 셋업:

1. Cloudflare 계정 + 도메인 연결 (무료)
2. `cloudflared tunnel login`
3. `cloudflared tunnel create aimu-backend`
4. DNS 레코드 추가
5. 영구 URL: `https://api.yourdomain.com` → 변경 X

자세한 절차는 https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/ 참고.
