# 백엔드 요청 — 소셜 로그인(OAuth) 앱(APK) 복귀 리다이렉트 지원 (`client=app`)

작성일: 2026-09-20
요청 출처: 모바일 앱 v3.194 (PLAN.md) — APK에서 구글/카카오 로그인이 완결되지 않는 구조적 문제(사용자 리포트: "로그인해도 앱이 로그인되지 않고 다시 로그인을 누르게 됨")

## 배경

- 현행 소셜 로그인은 SDK 미사용, 브라우저 리다이렉트 방식입니다: 앱이 `GET /api/auth/oauth/{provider}/login`을 브라우저로 열면 → OAuth 진행 → 백엔드가 최종적으로 `{frontend_url}/oauth/callback#token=JWT` 로 리다이렉트.
- 이 콜백은 **웹 프론트 주소**라서, 네이티브 앱(APK)에서는 로그인에 성공해도 토큰이 외부 브라우저의 웹 페이지에 남고 **앱으로 돌아오지 않습니다**. 앱은 로그인 사실을 알 수 없습니다.
- 앱 v3.194는 `expo-web-browser`의 `openAuthSessionAsync(loginUrl + '?client=app', 'aidol://oauth/callback')` 방식으로 전환했고, `aidol://oauth/callback#token=JWT` 딥링크 수신 처리(실행 중 + 콜드 스타트)도 구현 완료 상태입니다. **백엔드 리다이렉트만 지원되면 즉시 동작합니다.**

## 요청 사항

### 1) `client=app` 파라미터 지원 (필수)

`GET /api/auth/oauth/{provider}/login?client=app` 으로 진입한 OAuth 플로우는, 성공 시 최종 리다이렉트를 아래로 보내 주세요.

```
aidol://oauth/callback#token={JWT}
```

- `provider`: `google` | `kakao` (naver는 v3.194에서 UI 제거 — 대응 불필요)
- `client=app` 값은 OAuth `state` 에 실어 콜백까지 전달하거나 세션에 보관해 주세요(콜백 시점에 어느 클라이언트인지 알아야 함).
- `client` 미지정(웹)은 **현행 그대로** `{frontend_url}/oauth/callback#token=JWT` 유지.
- 토큰은 지금처럼 fragment(`#token=`)로 부탁드립니다 — 쿼리스트링(`?token=`)은 서버 로그/Referer에 남을 수 있습니다. (앱 파서는 방어적으로 둘 다 수용하긴 합니다.)

### 2) 실패 시에도 앱으로 복귀 (권장)

OAuth 실패/거부 시 `client=app` 이면 아래로 리다이렉트해 주세요.

```
aidol://oauth/callback#error={URL인코딩된 짧은 사용자용 문구}
```

- 앱은 `error` 값을 **문자열·80자 이내일 때만** 그대로 표시하고, 아니면 고정 문구로 대체합니다(v3.194 방어 반영). 내부 스택트레이스/raw 예외 문구는 보내지 마세요.
- 미지원 시에도 앱은 크래시 없이 동작합니다(사용자가 브라우저를 닫으면 조용히 복귀).

### 3) 프리플라이트 제거에 따른 확인 (참고)

- 앱이 기존에 버튼 탭마다 보내던 **axios 프리플라이트 `GET /auth/oauth/{p}/login`을 v3.194에서 제거**했습니다. 이 호출은 RN XHR이 302를 끝까지 따라가 OAuth state를 선점/소모시키는 부작용이 있었습니다("두 번째 시도에 null 오류" 유력 원인). 서버측에서 동일 세션의 이중 state 발급/소모 흔적이 로그에 있는지 확인 부탁드립니다.
- OAuth 키 미설정 안내가 필요하면, 리다이렉트를 따라가지 않고 JSON만 주는 **별도 status 엔드포인트**(예: `GET /api/auth/oauth/status` → `{ google: true, kakao: false }`)를 주시면 앱에서 버튼 비활성/안내에 쓰겠습니다(선택).

### 4) `frontend_url` 설정값 점검 (참고)

- 웹 콜백 URL 조립에 쓰는 `frontend_url` 이 미설정이면 `null/oauth/callback` 같은 주소가 만들어질 수 있습니다 — 사용자에게 표시된 "null 에 접근할 수 없습니다" 문구의 후보이기도 하니 운영 env 값 확인 부탁드립니다.

## 앱측 상태 (완료)

| 항목 | 상태 |
| --- | --- |
| `expo-web-browser` 도입, `openAuthSessionAsync(… ?client=app, aidol://oauth/callback)` | 완료 (components/auth/SocialLoginButtons.tsx) |
| `aidol://oauth/callback#token=` 딥링크 수신(실행 중 + 콜드 스타트) → 세션 열기 | 완료 (App.tsx useOAuthCallback) |
| 콜백 미수신/취소 시 조용히 복귀(크래시·무한 busy 없음) | 완료 |
| 서버 오류 문구 검증(문자열·80자 이내만 노출) | 완료 |

앱 스킴 `aidol` 은 app.json에 등록되어 있어 스토어 재심사 없이 현행 APK 빌드로 동작합니다.
